# Vocabulary 조작 보완

2026-09-22. 요청한 Ctrl+휠 확대·축소, 한국어 뜻 오른쪽 정렬, 선택 삭제에 이어 전체 선택과 순서 섞기를 추가했습니다.

## 동작

- Vocabulary 안에서 Ctrl+휠을 돌리면 75~200%로 확대·축소합니다. 기존 버튼, 보기 전환·화면 왕복 시 배율 유지, 출력 PDF와 Reader의 독립적인 배율은 유지합니다.
- 일반 휠은 스크롤합니다. Ctrl+휠은 passive가 아닌 리스너에서 기본 WebView 확대를 막고, 연속 입력은 requestAnimationFrame으로 묶습니다. 다른 화면으로 이동하면 리스너와 예약된 프레임을 정리합니다. 픽셀/행/페이지 단위 휠 입력을 처리합니다.
- Simple View의 한국어 뜻과 Detailed View의 각 문맥의 뜻을 행 오른쪽 끝에 정렬합니다. 설명·원문은 기존 정렬을 유지합니다.
- 두 보기에서 항목 앞 체크박스로 여러 항목을 고른 뒤 `선택 삭제 (N)`를 누릅니다. 보기 전환 시 선택은 유지하고, 검색·논문 필터 변경 또는 Reader 이동 시 해제합니다. 선택 없이 삭제할 수 없고, 처리 중 중복 삭제와 내보내기는 비활성화됩니다.
- `전체 선택` 체크박스는 현재 검색·논문 필터 결과의 모든 항목에 적용합니다. 화면 밖에 있는 항목도 포함하며, 다시 누르면 전체 해제합니다. 일부만 선택하면 부분 선택 상태로 표시합니다. 목록을 읽는 중이거나 비어 있거나 오류가 있거나 삭제 중이면 비활성화됩니다.
- `순서 섞기`는 현재 결과를 Fisher–Yates 방식으로 섞습니다. 우연히 전체 순서가 같아지면 두 항목을 교환해 버튼을 누른 효과가 나타나도록 합니다. 선택은 위치가 아닌 항목 ID로 유지하며 DB·문맥·조회 횟수·API 비용을 변경하지 않습니다.
- 섞은 순서는 두 보기 전환과 확대·축소 중에 유지되며 PDF 내보내기에도 반영됩니다. 검색·논문 필터 변경, 화면 재진입, 삭제 완료 등으로 DB를 다시 읽으면 기본 순서로 돌아갑니다. 항목이 2개 미만이거나 읽기/삭제/내보내기 중이면 섞기를 비활성화합니다.
- 선택한 항목은 논문 필터와 관계없이 모든 문맥·조회 기록·Cache·Highlight와 함께 삭제합니다. 삭제 버튼 아래에 이 범위를 표시합니다. 항목에는 저장한 구·문장도 포함됩니다.
- 다른 단어, PDF 파일과 Paper 정보, 초기 크레딧·과거 API 사용 비용, 색상 설정은 유지합니다. 이미 발생한 비용을 환급하거나 API를 호출하지 않습니다.
- 기존 DB 버전 4에서 관련 행을 하나의 SQLite 트랜잭션으로 삭제합니다. 일부 삭제 실패 시 전체를 롤백합니다. 실패 메시지와 기존 선택을 유지해 다시 시도할 수 있습니다. 성공한 삭제는 앱 재실행 뒤에도 유지됩니다.
- Reader의 현재 Highlight 목록도 갱신합니다. PDF Canvas/Text Layer와 렌더 큐·캐시·DPR 제한·PDF Zoom·Linux 스크롤 설정은 그대로입니다.

## 자동 검증

전체 **96개 통과**: Vitest 19, Rust 29, Playwright 48. 선택 삭제까지의 93개에 전체 선택·순서 섞기 UI 테스트 3개를 추가했습니다. 기존 빈 단어장 테스트의 ‘삭제 버튼 없음’ 기대만 선택 삭제 요구에 맞춰 ‘선택 없이 삭제 불가’로 변경했습니다.

- 실제 휠 입력으로 확대·축소, 상·하한, 일반 스크롤, WebView 확대 방지, Reader와 배율 분리, 화면 왕복과 행 단위 입력을 확인했습니다.
- 1200px/640px 화면과 확대 상태에서 Simple/Detailed 뜻의 오른쪽 정렬, 가로 넘침 없음을 검증하고 스크린샷을 확인했습니다.
- 단어와 문장 다중 삭제, 논문 필터 상태의 전체 문맥 삭제, 캐시 무효화, 다른 단어의 캐시/Highlight 유지, 열린 Reader의 즉시 갱신과 동일 Canvas/Text 노드 보존을 확인했습니다.
- 삭제 오류/재시도, 처리 중 중복 실행 방지, 필터·화면 변경 시 선택 해제를 검증했습니다.
- 화면 밖 항목을 포함한 30개 전체 선택/해제, 부분 선택 표시, 두 보기 전환 시 선택 유지, 검색·논문 필터와 조합한 선택 삭제가 숨겨진 항목을 삭제하지 않는지 확인했습니다.
- 순서 섞기 후 누락·중복 없이 뜻/문맥 연결과 선택 ID가 유지되는지, 보기/배율 변경으로 다시 섞이지 않는지, 2개 항목에서도 순서가 바뀌는지, DB/API가 변경되지 않는지 확인했습니다.
- 실제 SQLite를 재연결해 영구 삭제, 외래 키 정합성, Paper/파일/색상/비용 유지, 중복·없는 ID 처리와 다중 삭제 도중 실패의 전체 롤백을 확인했습니다.
- 기존 PDF 열기·드롭·단어/드래그/삼중 클릭 선택·번역/설명·하이라이트 복원/색상/취소·줌·말풍선·빠른 스크롤·API Cache/비용·PDF 내보내기 회귀 테스트도 통과했습니다.

실제 유료 API는 호출하지 않았습니다. UI 테스트는 기존 IPC 대역을, 데이터 무결성 테스트는 임시 실제 SQLite를 사용합니다. 삭제 테스트에 사용자 DB를 사용하지 않습니다.

```bash
source .tools/env.sh
npm test
OPENAI_API_KEY= npm run test:rust
npm run test:e2e
OPENAI_API_KEY= cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
OPENAI_API_KEY= npm run tauri build -- --no-bundle
PKG_CONFIG_PATH="$PWD/.tools/bundle-pkgconfig" APPIMAGE_EXTRACT_AND_RUN=1 npm run tauri bundle
```

UI 확인 화면은 `.tools/vocabulary-controls-verification/`에 있습니다. Reader의 `pageRendering.ts`와 `useReaderZoom.ts`는 기존 최적화 코드와 동일함을 비교했습니다. 이번 변경은 스크롤 성능 개선을 주장하지 않으며 기존 회귀 검증으로 동작 보존을 확인합니다.

## 빌드 및 실제 데스크톱 확인

TypeScript/Vite, Clippy(`-D warnings`), Tauri 릴리스와 DEB/RPM/AppImage 빌드가 통과했습니다. Vite의 기존 대용량 청크 경고는 남아 있습니다.

선택 삭제를 추가했을 때에는 당시 최종 AppImage를 분리된 테스트 DB로 실행해 Linux WebKit의 Ctrl+휠 확대/축소(100%→120%→100%), 두 보기의 오른쪽 뜻 정렬, 보기 전환 시 체크 유지와 실제 삭제 IPC를 확인했습니다. 삭제한 단어의 문맥 4개와 Highlight 1개가 사라지고, 별도 문장 항목/문맥 2개, Paper 2개와 크레딧은 유지됐습니다. 앱을 완전히 닫고 다시 실행한 뒤에도 삭제된 단어가 복원되지 않았습니다. 전후 SQLite 기록과 화면은 같은 검증 폴더에 보관합니다.

전체 선택·순서 섞기는 Vocabulary의 React 화면과 스타일만 변경했습니다. 추가 후 전체 테스트와 Tauri 빌드를 다시 실행했으며, 두 보기의 640px/1200px 확대 화면에서 새 조작부의 배치도 확인했습니다.
