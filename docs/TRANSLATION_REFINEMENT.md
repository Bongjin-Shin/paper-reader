# 설명 저장 및 본문 번역 개선 검증 · 2026-09-24

## 변경 범위

- 선택 텍스트의 설명은 Vocabulary·Context·Lookup Count·Highlight를 변경하지 않습니다. 독립 SQLite 설명 캐시에 결과를 저장해 재사용하며 기존 설명 기록은 그대로 둡니다. 같은 문맥의 기존 하이라이트에서 캐시된 설명을 다시 보는 기능도 유지합니다. 선택 텍스트 번역의 자동 저장과 비용 기록은 유지합니다.
- 줄을 합치기 전에 반복되는 단 사이 간격을 찾습니다. 위첨자는 본문 행의 세로 겹침에 따라 합치고, 왼쪽 단 다음 오른쪽 단의 순서로 문장을 구성합니다. 한 단 문서, 전체 너비 제목/초록, 짧은 제목의 다음 줄, 단 안의 큰 제목을 각각 검증했습니다. 읽는 순서가 바뀌어도 좌표는 실제 DOM Range에서 구합니다.
- API 및 Codex 본문 번역의 완성된 문장부터 표시합니다. Codex에는 문장 배열을 직접 반환하는 스키마를 사용해 JSON 문자열 안에 JSON을 다시 넣던 구조를 제거했습니다. 완료 전 결과는 임시 표시이며 최종 검증에 실패하면 캐시·비용을 저장하지 않습니다. 제공자/모델/요금은 바꾸지 않았습니다.
- 원문 hover도 번역문과 원문에 회색 음영을 표시하며 번역 패널 안에서 대응 문장을 보여줍니다. 원문 드래그 선택은 가로채지 않습니다. pointermove는 RAF 단위로 처리하고, 일반 스크롤은 활성 원문 hover를 해제할 때 외에는 React state를 갱신하지 않습니다.
- 오른쪽 번역창 경계를 드래그해 너비를 조절합니다. 드래그 중에는 RAF로 너비만 반영하고 마지막 값은 재실행 후에도 유지합니다. 페이지 너비 맞춤과 줌 후 좌표도 검증합니다.

## 측정과 한계

네트워크/모델 호출 없이 동일한 로컬 25페이지 두 단 논문의 1~4페이지를 PDF.js로 추출했습니다. 단일 실행의 관찰값이며 엄밀한 속도 비교 지표는 아닙니다.

| 페이지 | 기존 추출 시간 | 변경 후 추출 시간 |
|---|---:|---:|
| 1 | 61.8 ms | 48.6 ms |
| 2 | 16.2 ms | 15.0 ms |
| 3 | 17.2 ms | 14.8 ms |
| 4 | 31.2 ms | 19.5 ms |

추출은 수십 ms 수준이어서 이것만으로 모델 응답 전체의 긴 대기를 해결할 수는 없습니다. 기존에는 전체 JSON과 완료 이벤트까지 기다려야 첫 문장을 볼 수 있었습니다. 지금은 완성된 문장부터 읽을 수 있습니다. 모의 HTTP 서버 및 Codex 서버가 첫 문장의 수신 확인을 받을 때까지 마지막 이벤트를 보내지 않는 테스트로 조기 전달을 확인했습니다. 네이티브 앱에서도 `3/7 문장` 상태에서 세 문장이 보이는 화면을 확인했습니다.

실제 모델의 번역 품질이나 전체 요청 시간은 이번 검증에서 측정하지 않았습니다. 유료 API 또는 실제 구독 모델 호출을 수행하지 않았습니다. 복잡한 표, 세 단 이상, 비표준 PDF 텍스트 배치는 여전히 자동 읽기 순서에 한계가 있습니다.

## 회귀 검증

- 설명: 단어·구/문장, 기존 단어 재설명, 재실행·제공자 전환 캐시, 이전 설명 데이터 보존, 번역 후 저장, 실패·DB 쓰기 오류 시 비용 rollback.
- 스트리밍: UTF-8 바이트 경계, escape·중괄호 포함 텍스트, ID 순서 재배치, 누락·중복·빈 결과, 연결 종료·실패 turn, 다른 thread/turn/item 및 commentary 무시, 최종 실제 token usage 반영.
- 페이지: 한 단/두 단/좁은 단 간격, 큰 제목/위첨자/줄 끝 하이픈, 페이지별 캐시 및 layout version 이관, 문서 전환 중 응답, 회전·줌·스크롤 후 음영 좌표, 양방향 hover, 부분 결과와 실패 재시도.
- Reader/Library/Vocabulary: 기존 선택·말풍선·하이라이트 복원·스크롤/줌 최적화·다중 파일/다중 선택·정렬·메모·undo/redo·출력 테스트 유지. 기존에 설명으로 하이라이트를 생성하던 회귀 시나리오는 새 요구에 맞게 번역으로 변경했습니다.

검증 로그와 네이티브 화면은 `.tools/translation-refinement/`에 있습니다. 네이티브 검증은 별도 Xvfb 화면, 테스트 PDF, 테스트 DB, 모의 Codex 서버만 사용합니다. 사용자 DB는 변경하지 않았습니다.

최종 자동 검증: Vitest 56개, Rust 79개, Playwright 138개, 총 **273개 통과**. 기존 외부 인증 수동 테스트 1개는 제외했습니다. `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, Tauri release 빌드를 통과했습니다.

네이티브 검증에서는 스트리밍 중 일부 문장 표시, 양방향 회색 음영, 번역창 너비 조절·페이지 너비 맞춤·Ctrl+휠 확대를 확인했습니다. 설명 호출 후 SQLite는 설명 캐시 1개, Vocabulary/Context/Highlight 각각 0개였습니다. 같은 단어를 번역한 뒤 Vocabulary/Context/Highlight가 각각 1개 생겼으며 본문 캐시는 그대로 1개였습니다. 모의 ChatGPT 호출이므로 API 비용 기록은 0개입니다.

AppImage/deb/rpm 패키징 및 설치본 갱신을 완료했습니다. 설치본을 격리된 DB로 재실행해 본문 캐시·너비 540px·기존 컬러 하이라이트·양방향 회색 음영을 확인했고, 재실행과 하이라이트 재열람 후 모의 모델 호출 수는 3회로 유지됐습니다.
