# 페이지별 본문 번역

PDF Reader 상단의 **본문 번역**을 누르면 현재 페이지를 한국어로 번역하고 오른쪽에 표시합니다. 페이지별 번역을 하나의 연속된 문서로 표시합니다. 원문 또는 번역창을 스크롤하면 페이지별 진행 위치에 맞춰 반대쪽도 이동하며, 이전 페이지의 번역을 교체하지 않습니다. 이전/다음 버튼은 원문 위치를 이동합니다. 저장된 번역은 바로 불러오며, 아직 번역하지 않은 페이지는 **이 페이지 번역**을 눌러 실행합니다. 논문 전체를 자동으로 호출하지 않습니다.

원문 또는 번역 문장을 가리키면 양쪽의 대응 문장에 회색 음영이 표시됩니다. 원문을 가리키면 번역 패널 안에서 대응 문장이 보이도록 이동합니다. 원문 드래그 선택은 가로채지 않습니다. 클릭하면 표시가 유지되고 필요한 경우 원문 위치로 이동합니다. 패널을 닫으면 회색 음영만 사라집니다. 기존 Vocabulary와 컬러 하이라이트는 그대로 유지됩니다.

번역창의 왼쪽 경계선을 드래그해 너비를 조절합니다. 경계선에 키보드 포커스를 둔 후 좌우 방향키로도 조절할 수 있으며 너비는 재실행 후에도 유지됩니다. 최소 번역창 너비는 240px이고 Reader 영역을 남겨 둡니다.

## 저장 및 연결

- 기존 **번역 연결**에서 선택한 API 또는 ChatGPT 구독을 사용합니다. 자동으로 다른 제공자에 전환하지 않습니다.
- SQLite v13의 `page_translations`에 논문·페이지별 원문, 문장 번호, PDF 좌표와 번역을 저장합니다. 재실행 후에도 재사용합니다.
- 본문 번역은 Vocabulary나 영구 하이라이트를 만들지 않습니다.
- 선택 텍스트의 **설명**도 Vocabulary·Context·조회 횟수·Highlight를 변경하지 않으며, 별도 `explanation_cache`에서 재사용합니다. 이전 버전의 설명 기록은 유지합니다. 선택 텍스트 **번역**의 자동 저장은 그대로입니다.
- 레이아웃 버전 1·2·3·4·5의 본문 캐시는 다음 명시적 번역 요청에서 다시 생성합니다. 원문 순서와 좌표가 잘못된 기존 캐시가 수정 후에도 재사용되는 것을 막습니다. 전체 논문을 자동 재번역하지 않습니다.
- API 성공 시 기존 Responses token usage 계산을 사용하며 번역 저장과 비용 기록을 함께 commit합니다. 호출 오류·문장 누락·중복 등 유효하지 않은 결과는 저장하거나 앱의 예상 잔액에서 차감하지 않습니다. ChatGPT 구독과 캐시 재사용은 API 예상 잔액에 영향을 주지 않습니다.
- 다른 논문을 열어도 이전 요청 결과를 새 논문에 표시하지 않습니다. 이미 전송된 요청은 완료되면 원래 논문의 캐시에 저장됩니다.

## 문장과 좌표

번역 실행 시 해당 페이지와 문장 연결에 필요한 앞뒤 페이지의 임시 PDF.js Text Layer를 만듭니다. 글자의 기준선과 크기로 위·아래첨자를 같은 행에 포함하고, 반복되는 단 사이 간격을 먼저 판별해 왼쪽 단 다음 오른쪽 단의 순서로 정리합니다. 시각적인 줄은 문장 경계로 사용하지 않습니다. 이탤릭체·줄 간격 변화·단 이동으로 문장이 잘리지 않도록 본문을 연결한 뒤 문장 부호를 기준으로 분리합니다. Fig., Eq., e.g. 같은 약어와 소수점도 고려합니다. 제목·문단·수식 블록은 구분합니다. 좌표는 DOM Range에서 PDF 좌표로 변환하며 AI가 생성하지 않습니다.

번역문은 원문 문단에 따라 묶어 창 너비에 맞춰 자동 줄바꿈하고 양쪽 정렬합니다. 제목과 독립 수식은 따로 배치합니다. 같은 문단 안에서도 문장마다 원문과 양방향으로 대응합니다. 같은 크기의 굵은 INTRODUCTION 같은 절 제목도 별도 블록으로 인식합니다. 본문의 연속된 원고 줄 번호는 제외하고, 블록의 상대 글자 크기·주된 굵기·기울임을 보존합니다. 한국어 길이와 창 너비가 다르므로 원본의 물리적인 줄 수·글꼴·페이지 모양까지 복제하지는 않습니다.

선택 가능한 수식 기호·수학 폰트로 인식한 수식은 원본 PDF 영역의 이미지로 표시합니다. 본문 안의 수식은 번역문 안에, 독립 수식은 별도 블록에 넣으며 분수선·첨자·괄호를 원본 모습으로 유지합니다. AI에는 문장 번호·원문과 수식 자리표시자·추출 텍스트만 전달합니다. 반환 문장 번호와 각 수식 자리표시자가 정확히 한 번씩 존재하는지 검증합니다. 수식 이미지·좌표는 AI에 보내지 않습니다.

수식이 있는 현재 번역 페이지에 한해서 Canvas를 한 번 추가 렌더링하고 영역별 이미지를 재사용합니다. 최대 400만 픽셀·2배 배율로 제한하고, hover·Reader 줌·번역창 크기 변경 때 다시 그리지 않습니다. 번역 구간이 화면에서 멀어지거나 패널을 닫으면 해제합니다. 수식 영역은 번역문·문단 정보와 함께 layout version 6 캐시에 저장하고 이미지는 필요할 때 로컬 PDF에서 다시 만듭니다.

회색 레이어는 기존 페이지 surface 안에서 확대·스크롤과 함께 이동합니다. 문장 hover는 Canvas/Text Layer를 새로 만들지 않습니다. 현재 페이지 추적은 IntersectionObserver를 사용합니다. 연속 스크롤 동기화는 캐시한 페이지 위치를 이진 탐색하여 requestAnimationFrame 안에서 scrollTop만 갱신하고, 스크롤 이벤트마다 React state를 갱신하지 않습니다. 기존 페이지 캐시·렌더 큐·줌 중 Text Layer 재사용을 유지합니다.

이미지로만 된 PDF나 이미지로 삽입되어 텍스트가 없는 수식의 OCR은 지원하지 않습니다. 수식은 편집 가능한 LaTeX가 아닌 원본 이미지입니다. 복잡한 표·다단·비표준 PDF에서는 자동 문장 구분과 읽는 순서가 원문 편집 구조와 다를 수 있습니다. 한 페이지의 추출 텍스트가 20,000자 또는 256문장을 넘으면 요청을 보내지 않고 부분 선택 번역을 안내합니다.

## 응답 대기 개선

Responses API와 Codex 연결 모두 스트리밍으로 받습니다. 완성된 문장 객체부터 순서대로 화면에 표시하고 `n/전체 문장` 진행 상태를 제공합니다. Codex에도 중첩 JSON 문자열 대신 문장 배열의 직접 출력 스키마를 전달합니다. 전체 응답의 완료·문장 번호·누락·중복을 최종 검증한 뒤에만 캐시와 비용을 기록합니다. 실패한 임시 결과는 제거하며 다시 시도할 수 있습니다. 토큰마다 React를 갱신하지 않고 완성된 문장이 있을 때만 갱신합니다.

[Responses 스트리밍](https://developers.openai.com/api/docs/guides/streaming-responses), [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [Codex App Server](https://learn.chatgpt.com/docs/app-server)의 공식 이벤트와 스키마를 사용합니다. 모델·연결·요금 설정은 유지합니다. 처음 읽을 수 있는 결과의 대기 시간을 줄이는 변경이며 모델 자체의 처리 시간이나 네트워크 지연이 없어지는 것은 아닙니다.

## 검증

자동 테스트는 문장 누락·중복·실패/재시도, DB 재실행·마이그레이션·비용·캐시, ChatGPT app-server 모의 프로토콜, 두 단 읽기 순서, 줄 끝 하이픈, 회전 0/90/180/270도 및 UserUnit, 줌·스크롤 후 좌표, 기존 하이라이트/단어 선택, 페이지·문서 변경 중 비동기 결과, 이미지 페이지를 포함합니다. 실제 과금 요청 없이 모의 응답으로 연결·저장·UI 동작을 검증합니다.

최신 검증 결과는 [굵은 본문·수식·말풍선 보정](SENTENCE_BUBBLE_FIXES.md)을 참고하세요. 이전 변경은 [본문 번역 개선 검증](TRANSLATION_REFINEMENT.md)에 기록했습니다.

## 페이지 경계 문장 (2026-10-08)

페이지 마지막 본문 문장이 끝나지 않은 경우 다음 페이지의 첫 본문 문장을 이어 붙입니다. 다음 페이지의 첫 문장도 앞페이지를 참고해 같은 완성 문장을 사용합니다. 한 문장이 여러 페이지에 걸친 경우 끝까지 연결합니다. 제목·페이지 번호·캡션은 연결 대상으로 삼지 않으며, 약어·하이픈을 처리합니다. 양쪽 페이지에 같은 전체 번역을 중복 표시하되 회색 음영은 해당 문장이 걸친 모든 페이지의 원문을 함께 표시합니다. 앞페이지나 뒷페이지의 번역을 선택하면 양쪽 번역도 동시에 표시됩니다. 각 페이지에 속한 원문 좌표를 함께 저장하므로 반대쪽 페이지가 아직 번역되지 않았어도 해당 원문을 표시할 수 있습니다.

수식 토큰은 원본 페이지별로 구분하며, 이어진 문장 안의 수식도 원본 페이지에서 이미지를 가져옵니다. SQLite의 `shared_sentence_translations`는 같은 원문과 수식 정보의 최종 번역을 재사용하므로 페이지 번역 순서와 무관하게 동일한 문장 표현을 유지합니다. 본문 캐시는 레이아웃 버전 6에서 전체 문장 음영과 문서 구조를 적용하며 이전 캐시는 다음 명시적 번역 요청 때 갱신합니다.

복잡한 머리말·각주·편집 레이아웃에서는 문장 연결을 자동으로 잘못 판단할 수 있습니다. 선택 가능한 텍스트가 없는 인접 페이지는 연결할 수 없습니다.

## 말풍선 연결선

활성 말풍선 중심과 선택 원문 음영의 바깥 경계 중심을 점선으로 연결합니다. 여러 페이지에 걸친 선택은 각 페이지의 원문 중심으로 각각 연결합니다. 말풍선 드래그·확대·페이지 재배치 때 좌표를 갱신하며, 일반 스크롤에서는 원문과 같은 문서 좌표로 이동합니다. 연결선은 클릭·텍스트 선택을 가로채지 않습니다.
