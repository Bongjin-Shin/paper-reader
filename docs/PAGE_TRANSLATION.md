# 페이지별 본문 번역

PDF Reader 상단의 **본문 번역**을 누르면 각 원문 페이지 오른쪽에 해당 페이지의 번역이 붙습니다. 원문과 번역은 하나의 페이지 행으로 표시되며, 위·아래 경계가 일치합니다. 행 사이에는 페이지 여백이 있고 전체 문서는 하나의 스크롤로 함께 이동합니다. 원문의 크기·회전·확대 비율이 바뀌어도 번역 영역은 해당 원문의 높이에 맞춰집니다.

긴 번역은 해당 페이지 안에서 별도로 스크롤할 수 있습니다. 내부 스크롤이 맨 위·아래에 도달하면 전체 문서의 스크롤로 이어집니다. 원문이나 페이지 바깥 여백에서 스크롤하면 전체 문서가 이동합니다. 각 번역 페이지에 `현재/전체 페이지`를 표시하고, 상단 이전/다음 버튼으로 페이지 쌍을 이동합니다.

첫 페이지도 자동으로 번역하지 않으며, 각 페이지의 **이 페이지 번역** 버튼을 눌러야 새 번역을 시작합니다. 저장된 번역은 바로 불러옵니다. **재번역**으로 선택한 페이지를 다시 번역할 수 있으며, 논문 전체를 자동으로 호출하지 않습니다.

재번역을 시작하면 해당 번역 페이지의 내부 스크롤을 맨 위로 되돌리고 이전 표시 내용을 비운 뒤, 새로 도착한 문장을 순서대로 보여 줍니다. 중단하면 그때까지 받은 문장을 화면에 유지합니다. 새 번역이 끝나기 전까지 기존 완료본은 디스크에 보관하므로 중단 후 앱을 다시 열면 이전 완료본을 볼 수 있습니다.

원문 또는 번역 문장을 가리키면 양쪽의 대응 문장에 회색 음영이 표시되며 스크롤 위치는 바꾸지 않습니다. 원문 드래그 선택은 가로채지 않습니다. 클릭하면 표시가 유지되고 필요한 경우 원문 위치로 이동합니다. 번역을 닫으면 회색 음영만 사라집니다. 기존 Vocabulary와 컬러 하이라이트는 그대로 유지됩니다.

원문과 번역 사이 경계선을 드래그하면 모든 페이지의 번역 너비를 함께 조절합니다. 경계선에 키보드 포커스를 둔 후 좌우 방향키로도 조절할 수 있으며 너비는 재실행 후에도 유지됩니다. 최소 번역창 너비는 240px입니다. 번역을 열거나 너비를 조절해도 사용자가 선택한 배율과 너비 맞춤 설정을 유지합니다. 너비 맞춤을 직접 켜 둔 경우에만 원문과 번역이 Reader 너비에 들어오도록 배율을 조절합니다.

## 저장 및 연결

- 기존 **번역 연결**에서 선택한 API 또는 ChatGPT 구독을 사용합니다. 자동으로 다른 제공자에 전환하지 않습니다.
- SQLite v13의 `page_translations`에 논문·페이지별 원문, 문장 번호, PDF 좌표와 번역을 저장합니다. 재실행 후에도 재사용합니다.
- 본문 번역은 Vocabulary나 영구 하이라이트를 만들지 않습니다.
- 선택 텍스트의 **설명**도 Vocabulary·Context·조회 횟수·Highlight를 변경하지 않으며, 별도 `explanation_cache`에서 재사용합니다. 이전 버전의 설명 기록은 유지합니다. 선택 텍스트 **번역**의 자동 저장은 그대로입니다.
- 레이아웃 버전 7 이하의 본문 캐시는 다음 명시적 번역 요청에서 다시 생성합니다. 원문 순서와 좌표가 잘못된 기존 캐시가 수정 후에도 재사용되는 것을 막습니다. 전체 논문을 자동 재번역하지 않습니다.
- API 성공 시 기존 Responses token usage 계산을 사용하며 번역 저장과 비용 기록을 함께 commit합니다. 호출 오류·문장 누락·중복 등 유효하지 않은 결과는 저장하거나 앱의 예상 잔액에서 차감하지 않습니다. ChatGPT 구독과 캐시 재사용은 API 예상 잔액에 영향을 주지 않습니다.
- 다른 논문을 열어도 이전 요청 결과를 새 논문에 표시하지 않습니다. 이미 전송된 요청은 완료되면 원래 논문의 캐시에 저장됩니다.

## 문장과 좌표

번역 실행 시 해당 페이지와 문장 연결에 필요한 앞뒤 페이지의 임시 PDF.js Text Layer를 만듭니다. 글자의 기준선과 크기로 위·아래첨자를 같은 행에 포함하고, 반복되는 단 사이 간격을 먼저 판별해 왼쪽 단 다음 오른쪽 단의 순서로 정리합니다. 시각적인 줄은 문장 경계로 사용하지 않습니다. 이탤릭체·줄 간격 변화·단 이동으로 문장이 잘리지 않도록 본문을 연결한 뒤 문장 부호를 기준으로 분리합니다. Fig., Eq., e.g. 같은 약어와 소수점도 고려합니다. 제목·문단·수식 블록은 구분합니다. 좌표는 DOM Range에서 PDF 좌표로 변환하며 AI가 생성하지 않습니다.

번역문은 원문 문단에 따라 묶어 창 너비에 맞춰 자동 줄바꿈하고 양쪽 정렬합니다. 제목과 독립 수식은 따로 배치합니다. 같은 문단 안에서도 문장마다 원문과 양방향으로 대응합니다. 같은 크기의 굵은 INTRODUCTION 같은 절 제목도 별도 블록으로 인식합니다. 본문의 연속된 원고 줄 번호는 제외하고, 블록의 상대 글자 크기·주된 굵기·기울임을 보존합니다. 한국어 길이와 창 너비가 다르므로 원본의 물리적인 줄 수·글꼴·페이지 모양까지 복제하지는 않습니다.

선택 가능한 수식은 첨자를 가까운 기준 글자에 붙이고 조건식·여러 줄 수식을 하나로 묶어 PDF의 글자 위치·크기를 함께 전달하여 LaTeX로 변환하고 KaTeX와 Markdown으로 표시합니다. 문장을 나눌 때 수식 자리표시자 전체를 보호하므로 마침표 바로 뒤 수식도 잘리지 않습니다. 반환 문장 번호와 각 수식 자리표시자·LaTeX가 정확히 대응하는지 검증하며, 본문 수식을 표 이미지로 대체하지 않습니다. ToUnicode에 빠진 기호는 PDF 글꼴의 Encoding/Differences 이름이 있는 경우 그 이름으로 복구합니다. 과도하게 이스케이프된 LaTeX 명령과 집합 괄호도 렌더링 전에 정리합니다.

분수선의 위치와 글자 폭도 전달하며, 다른 단의 본문과 같은 높이에 있는 분자를 앞 문장에 붙이지 않습니다. 여러 줄 수식의 줄바꿈과 정렬 기호를 보존하고 수식 번호를 각 행 안에 배치하여 번호가 겹치거나 여러 `\\tag` 때문에 수식 전체가 표시되지 않는 문제를 방지합니다. 독립 수식은 본문 크기로 표시하며 창보다 넓으면 수식 안에서 가로 스크롤합니다. 번호 목록 등 Markdown 블록도 원문과 양방향으로 음영을 표시합니다.

표 영역은 본문 읽기 흐름과 번역 요청에서 제외합니다. 그림과 표는 캡션만 **그림·표 설명** 박스에 번역하며 표 원본 이미지나 셀별 번역은 표시하지 않습니다.

알고리즘 의사코드는 번역에서 제외합니다. 번호가 붙은 테두리형 알고리즘과 Input/Output·제어문·아래쪽 캡션이 있는 의사코드를 구분하며, 알고리즘을 설명하거나 참조하는 일반 본문은 번역합니다. 표와 알고리즘을 제외하더라도 원래 단의 위치 정보는 유지하여 맞은편 본문·소제목이 합쳐지지 않도록 합니다. 부록 표 번호와 행이 많은 표도 구분합니다. PDF 내장 글꼴을 불러온 뒤 위치를 측정하여 첫 추출과 다시 추출할 때의 차이를 줄입니다.

회색 레이어는 기존 페이지 surface 안에서 확대·스크롤과 함께 이동합니다. 문장 hover는 Canvas/Text Layer를 새로 만들지 않습니다. 현재 페이지 추적은 IntersectionObserver를 사용합니다. 원문과 번역을 같은 스크롤 컨테이너에 배치하므로 두 창의 scrollTop을 동기화할 필요가 없습니다. 페이지 렌더링 우선순위는 페이지 행의 위치를 포함한 문서 좌표로 계산합니다. 기존 페이지 캐시·렌더 큐·줌 중 Text Layer 재사용을 유지합니다.

이미지로만 된 PDF의 OCR은 지원하지 않습니다. 복잡한 표·다단·비표준 PDF에서는 영역 구분과 읽는 순서가 원문 편집 구조와 다를 수 있습니다.

이전의 한 페이지 20,000자·256문장 제한은 제거했습니다. 긴 페이지는 문장 순서대로 요청당 최대 64개 항목과 약 6,000자 분량으로 나누며, 수식 글자 정보도 분량 계산에 포함합니다. 유난히 긴 문장은 수식 토큰을 보존한 채 공백에서 나누고 최종 번역에서 다시 합칩니다. 원본 문장 번호와 음영 좌표는 유지합니다. API·ChatGPT·Claude 모두 동일한 분할 경로를 사용합니다. 전체 구간이 성공하고 문장·수식 누락 검증을 통과해야 한 페이지로 저장하며, 오류 시 불완전한 페이지를 캐시하지 않습니다. 페이지 번역은 계속 사용자가 명시적으로 실행해야 하며 분량이 많으면 요청 횟수·대기 시간·사용량이 증가할 수 있습니다.

## 응답 대기 개선

긴 문장의 분할에도 수식 글자 정보의 양을 반영합니다. 모델 응답에 문장·수식이 누락되거나 JSON이 불완전하면 해당 구간을 더 작게 나누어 최대 두 단계까지 다시 요청합니다. 취소·인증·네트워크 오류는 자동 재요청하지 않습니다. 수식만 남기고 주변 본문을 전부 빠뜨린 응답도 완료로 저장하지 않습니다. 번역이 중단되거나 실패하면 표시된 내용의 끝에도 미완료 상태를 안내합니다.

Responses API와 Codex 연결 모두 스트리밍으로 받습니다. 완성된 문장 객체부터 순서대로 화면에 표시하고 `n/전체 항목` 진행 상태를 제공합니다. Codex에도 중첩 JSON 문자열 대신 문장 배열의 직접 출력 스키마를 전달합니다. 전체 응답의 완료·문장 번호·누락·중복을 최종 검증한 뒤에만 캐시와 비용을 기록합니다. 실패한 임시 결과는 제거하며 다시 시도할 수 있습니다. 토큰마다 React를 갱신하지 않고 완성된 문장이 있을 때만 갱신합니다.

[Responses 스트리밍](https://developers.openai.com/api/docs/guides/streaming-responses), [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [Codex App Server](https://learn.chatgpt.com/docs/app-server)의 공식 이벤트와 스키마를 사용합니다. 모델·연결·요금 설정은 유지합니다. 처음 읽을 수 있는 결과의 대기 시간을 줄이는 변경이며 모델 자체의 처리 시간이나 네트워크 지연이 없어지는 것은 아닙니다.

## 검증

자동 테스트는 문장 누락·중복·실패/재시도, DB 재실행·마이그레이션·비용·캐시, ChatGPT app-server 모의 프로토콜, 두 단 읽기 순서, 줄 끝 하이픈, 회전 0/90/180/270도 및 UserUnit, 줌·스크롤 후 좌표, 기존 하이라이트/단어 선택, 페이지·문서 변경 중 비동기 결과, 이미지 페이지를 포함합니다. 실제 과금 요청 없이 모의 응답으로 연결·저장·UI 동작을 검증합니다.

## 페이지 경계 문장 (2026-10-08)

페이지 마지막 본문 문장이 끝나지 않은 경우 다음 페이지의 첫 본문 문장을 이어 붙입니다. 다음 페이지의 첫 문장도 앞페이지를 참고해 같은 완성 문장을 사용합니다. 한 문장이 여러 페이지에 걸친 경우 끝까지 연결합니다. 제목·페이지 번호·캡션은 연결 대상으로 삼지 않으며, 약어·하이픈을 처리합니다. 양쪽 페이지에 같은 전체 번역을 중복 표시하되 회색 음영은 해당 문장이 걸친 모든 페이지의 원문을 함께 표시합니다. 앞페이지나 뒷페이지의 번역을 선택하면 양쪽 번역도 동시에 표시됩니다. 각 페이지에 속한 원문 좌표를 함께 저장하므로 반대쪽 페이지가 아직 번역되지 않았어도 해당 원문을 표시할 수 있습니다.

수식 토큰은 원본 페이지별로 구분하며, 이어진 문장 안의 수식도 원본 페이지의 글자 정보를 사용해 LaTeX로 변환합니다. SQLite의 `shared_sentence_translations`는 같은 원문과 수식 정보의 최종 번역을 재사용하므로 페이지 번역 순서와 무관하게 동일한 문장 표현을 유지합니다. 본문 캐시는 레이아웃 버전 9에서 전체 문장 음영과 문서 구조를 적용하며 이전 캐시는 다음 명시적 번역 요청 때 갱신합니다.

복잡한 머리말·각주·편집 레이아웃에서는 문장 연결을 자동으로 잘못 판단할 수 있습니다. 선택 가능한 텍스트가 없는 인접 페이지는 연결할 수 없습니다.

## 말풍선 연결선

활성 말풍선 중심과 선택 원문 음영의 바깥 경계 중심을 점선으로 연결합니다. 여러 페이지에 걸친 선택은 각 페이지의 원문 중심으로 각각 연결합니다. 말풍선 드래그·확대·페이지 재배치 때 좌표를 갱신하며, 일반 스크롤에서는 원문과 같은 문서 좌표로 이동합니다. 연결선은 클릭·텍스트 선택을 가로채지 않습니다.

진행 중인 페이지에도 **재번역**과 **중단** 버튼을 제공합니다. 재번역은 기존 요청을 취소한 뒤 처음부터 다시 시작하며, 중단은 현재 요청과 이후 구간 요청을 중지합니다. API 연결은 HTTP 응답 future를 해제하고 ChatGPT·Claude 구독 연결은 해당 번역 작업을 중단합니다. 중단한 미완료 번역은 완성된 페이지로 저장하지 않으며 이전에 완료한 번역은 유지합니다. 늦게 도착한 결과는 새 작업의 화면이나 캐시를 덮어쓰지 못합니다.
