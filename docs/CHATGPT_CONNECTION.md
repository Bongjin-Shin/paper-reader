# ChatGPT 구독 연결

상단 **번역 연결 → 번역 방식: ChatGPT 구독 → ChatGPT 로그인**을 선택합니다. 기본 브라우저에서 본인 계정으로 로그인하면 앱이 완료 상태를 확인합니다. 이후 표시되는 `ChatGPT / 구독`을 눌러 연결 상태를 확인하거나 로그아웃할 수 있습니다. 로그인 취소와 로그인 페이지 다시 열기도 지원합니다.

이 방식은 ChatGPT 웹 채팅 API를 호출하는 것이 아니라, 공식 **Codex App Server**를 별도 로컬 프로세스로 실행하는 연동입니다. App Server는 현재 실험적 도구입니다. 구독의 Codex 사용 가능 여부·모델 권한·한도를 따르며 무제한 사용을 보장하지 않습니다. 로그인은 사용자가 브라우저에서 직접 완료해야 합니다.

## 기존 동작과 비용

- 기존 설치는 OpenAI API 설정으로 시작하며 사용자가 ChatGPT 구독을 선택하면 SQLite에 유지합니다. API로 되돌릴 수도 있습니다.
- 로그인 후 **번역 모델**에서 사용할 모델을 고릅니다. 공식 App Server의 `model/list` 응답으로 목록을 구성하고 SQLite에 선택을 저장합니다. 새 번역·설명 요청에 적용하며 저장된 캐시는 유지합니다. 초기 설정은 기존 `gpt-5.6-luna`이며, 선택 모델을 사용할 수 없으면 재선택을 안내합니다. 모델 목록 표시는 실제 요청 권한을 보장하지 않으며 다른 모델이나 유료 API로 자동 전환하지 않습니다.
- 단어/구/문장의 전체 텍스트와 기존 문맥·번역/설명 지시를 그대로 전달합니다. 매번 독립된 임시 대화를 사용하고 완료된 최종 JSON 결과만 저장합니다.
- SQLite Vocabulary, Context, Highlight, Lookup Count, Undo/Redo, 로컬 캐시는 동일한 저장 흐름을 사용합니다. 캐시는 로그인·API 키 검사보다 먼저 적용되며 연결 방식을 변경해도 재사용합니다.
- **ChatGPT 응답은 API 사용량 테이블에 기록하지 않으며 예상 잔액에서 차감하지 않습니다.** 처리 도중 번역 방식을 바꾸더라도 응답에 붙은 제공자 구분으로 비용을 처리합니다. 구독 사용량을 USD 잔액으로 환산하지 않습니다.
- API 모드의 기존 토큰 단가·누적 비용·초기 크레딧은 보존합니다. 실패한 응답이나 빈/불완전한 응답은 단어장·Highlight에 저장하지 않습니다.

## 로그인과 런타임

- `scripts/install-linux.sh`는 설치된 공식 Codex 실행 파일을 앱 데이터의 `runtime/codex`에 복사하여 사용합니다. 이 환경에서는 `codex-cli 0.153.4`로 검증했습니다. 설치 스크립트가 실행 파일을 찾지 못하면 기존 런타임 또는 사용자 PATH의 Codex를 찾습니다. 아무것도 없으면 설치 안내를 표시합니다.
- 로그인은 앱 데이터의 `chatgpt/` 아래에 Codex가 관리합니다. 다른 Codex의 인증 파일이나 브라우저 쿠키를 복사·추출하지 않습니다. 앱 폴더 권한은 Linux에서 700이며 토큰은 React나 SQLite에 전달하지 않습니다.
- 앱용 프로세스의 환경변수에서 API 키·액세스 토큰·기존 Codex 설정을 제외하고 ChatGPT 로그인만 허용합니다. 외부 브라우저는 서버가 반환한 허용된 HTTPS 인증 주소만 엽니다.
- 앱용 빈 작업 폴더, 읽기 전용 sandbox, 도구 기능 비활성화, 독립 프롬프트를 사용합니다. 예상하지 못한 도구·권한 요청은 거절하고 중단합니다. PDF 전체나 DB를 모델에 제공하지 않습니다.
- RPC는 20초로 제한하며 논문 채팅은 최대 10분 동안 응답을 기다립니다. 채팅에 추가 질문을 수락하면 대기 기한을 갱신합니다. 실패한 요청은 자동 재시도하지 않습니다. 앱 종료 시 대기 중인 요청과 자식 프로세스를 정리합니다.
- DB 버전 9는 `ai_preferences` 한 테이블만 추가합니다. 기존 단어·논문·폴더·메모·비용 데이터를 바꾸지 않습니다.

## 검증

Rust 프로토콜 테스트는 별도 Python 모의 App Server로 로그인/취소/로그아웃, 재시작, 모델 확인, 요청 텍스트 보존, 응답 순서 뒤바뀜, 다른 대화 이벤트, 실패·한도·비정상 출력·프로세스 종료·도구 거절, 비용 미차감, 캐시·저장·재실행을 확인합니다. 실제 설치된 공식 런타임은 인증 정보를 넣지 않은 독립 폴더에서 초기화합니다.

## 논문 채팅과 별도 모델 설정 (2026-10-08)

PDF Reader 상단의 **논문 채팅**으로 질문합니다. 현재 논문의 추출 텍스트, PDF 페이지 번호, 최근 대화(최대 20회·총 100,000바이트)를 함께 참고합니다. 채팅 모델과 effort는 번역 모델과 독립적으로 저장하며, 지원 effort와 기본값은 `model/list`의 실제 응답을 사용합니다. 모델을 바꾸면 effort는 해당 모델의 기본값으로 초기화됩니다. 채팅은 ChatGPT 구독 연결을 사용하며 API로 자동 전환하거나 API 잔액에서 차감하지 않습니다.

번역의 기존 자동 effort는 지원되는 `none`, `minimal`, `low` 중 첫 값이며 없으면 모델 기본값입니다. **번역 연결 → 번역 effort**에서 지원 목록 중 직접 선택할 수 있고 선택값을 별도로 저장합니다. 모델 변경 시 자동값으로 돌아갑니다. 이미 저장된 번역에는 새 effort가 소급 적용되지 않습니다.

채팅은 번역용 역할·JSON 응답 형식에서 분리한 논문 설명 전용 역할을 사용합니다. 정의·수식 기호·이유·과정·예시를 질문에 맞게 설명하도록 요청하고 `model_verbosity = high`를 전달합니다. effort는 사고 수준이며 답변 길이 설정과 별개입니다. 모델·질문·제공 문맥에 따라 실제 길이는 달라집니다.

응답의 `[p. N]`을 누르면 해당 PDF 페이지로 이동합니다. 성공한 질문·답변은 SQLite `paper_chat`에 논문별로 저장하며 앱 재시작 후에도 표시합니다. 요청 중 패널을 닫아도 대화를 유지합니다. 다른 논문으로 이동하는 동안 완료된 응답은 원래 논문에만 저장합니다. 실패 시 질문을 남겨 재시도할 수 있습니다. Enter로 전송하고 Shift+Enter로 줄바꿈하며 한글 조합 중 Enter는 전송하지 않습니다.

일반 논문은 선택 가능한 전체 본문을 전달합니다. 본문이 길면 현재 페이지·인접 페이지·질문 키워드에 가까운 발췌를 우선하여 약 110,000자로 제한하고 생략 여부를 모델에 알립니다. 이미지·OCR·텍스트로 추출되지 않은 수식은 지원하지 않습니다. 따라서 답변은 제공된 본문 기준이며 페이지 인용은 확인이 필요합니다.

구현은 [공식 OpenAI 문서의 모델 목록·effort·turn/start 프로토콜](https://learn.chatgpt.com/docs/app-server)을 따릅니다. 단위·UI·모의 App Server 테스트로 설정 분리, 지원하지 않는 effort 차단, 대화 저장·복원, 오류·재시도, 페이지 이동을 검증합니다. 실제 구독 사용량을 소비하는 실서비스 호출은 자동 테스트에 포함하지 않습니다.

### 실시간 채팅·수식·사용 한도

답변은 일반 Markdown으로 스트리밍하며 목록·굵은 글씨·표·코드·LaTeX 수식을 표시합니다. `$...$`, `$$...$$`, `\(...\)`, `\[...\]`를 지원하고 기존 채팅 기록에도 렌더러를 적용합니다. KaTeX는 로컬 번들로 실행하며 HTML·외부 이미지·신뢰가 필요한 수식 명령은 허용하지 않습니다. 렌더러와 CSS의 KaTeX 버전은 override로 통일합니다.

생각하거나 답변하는 동안 입력창을 사용할 수 있습니다. 전송 화살표나 Enter로 보낸 추가 질문은 기본적으로 대기열에 보관하며, 현재 답변이 완료되어 저장된 뒤 입력한 순서대로 새 답변을 요청합니다. 모델 준비 중에도 같은 방식으로 대기합니다. 이 기본 동작은 ChatGPT와 Claude에 공통으로 적용됩니다.

대기 질문마다 **바로 보내기**와 삭제 버튼을 표시합니다. **바로 보내기**를 직접 누른 경우에만 진행 중인 대화에 추가 메시지를 전달합니다. ChatGPT는 공식 `turn/steer`로 현재 답변에 보충 질문·정정·조건 변경을 반영합니다. 기존 질문의 목적과 미답변 부분을 유지하되, 정정은 이어지는 답변에 바로 적용하도록 요청합니다. 기존 답변을 무조건 끝낸 뒤 추가 질문을 처리하라는 순서 제약은 두지 않습니다. 명시적인 취소·요청 변경은 사용자의 의도에 따릅니다. 앱에서 중단 명령을 보내거나 기존 출력을 지우지는 않으며, 수락 확인을 받은 질문만 대기열에서 제거합니다. 전송 확인 중 기존 답변이 완료되어도 같은 질문을 중복 전송하지 않습니다.

이는 [공식 안내의 Queue와 Steer 구분](https://learn.chatgpt.com/docs/prompting#steering-and-queuing)에 맞춘 동작입니다. [Codex App Server](https://learn.chatgpt.com/docs/app-server#steer-an-active-turn)의 `turn/steer`는 현재 turn에 입력을 추가하고, `turn/interrupt`는 별도의 취소 명령입니다. 실제 반영 시점과 표현은 실행 중인 모델에 따라 달라질 수 있습니다. 현재 Claude 연결은 메시지를 수락한 뒤 현재 응답의 완료 시점에 같은 대화로 전달하므로, ChatGPT의 생성 중 반영과 시점이 다릅니다.

**답변 중단**은 `turn/interrupt`를 보내며 부분 답변과 중단 여부를 저장합니다. 중단·실패 때 대기 질문은 자동 전송하지 않으며 삭제하거나 **바로 보내기**로 다시 보낼 수 있습니다. Library·Vocabulary·다른 논문으로 이동하거나 채팅 패널을 닫아도 진행 중인 답변과 대기열 처리는 계속됩니다. 논문별로 입력 초안·선택 원문·질문 수정 초안·스크롤 위치를 앱 실행 중 유지합니다. 완료·중단된 답변은 SQLite에 저장하며 앱 재실행 후에도 복원합니다. 아직 전송하지 않은 초안과 대기열은 앱 종료 시에는 보존하지 않습니다.

왼쪽 아래에는 `account/rateLimits/read`와 `account/rateLimits/updated`로 제공되는 구독 한도별 잔여 **비율**을 표시합니다. 정확한 잔여 토큰 수는 제공되지 않습니다. 한도 주기(5시간·주간)와 실제 초기화까지 남은 시간(예: 2일 3시간)을 구분해 표시합니다. 30초마다, 그리고 앱으로 돌아올 때 갱신하며 마우스를 올리면 초기화·조회 시각이 보입니다. 새로고침 버튼도 있습니다. 조회 실패 시 이전 값임을 표시하고, 초기화 시각이 지나도 새 사용량을 확인하기 전에는 100%로 임의 변경하지 않습니다. 번역과 채팅이 같은 구독을 쓰므로 공통 한도이며 API 금액과 별개입니다. Claude 구독에도 같은 남은 시간 표시가 적용됩니다.

채팅창 왼쪽 경계를 드래그하거나 경계에 포커스를 둔 뒤 좌우 방향키를 눌러 너비를 조절합니다. 번역창·채팅창의 `− / +` 버튼 또는 각 창 안의 `Ctrl+휠`로 글자와 수식을 70~200%로 조절할 수 있습니다. 창 안에 포커스가 있을 때 `Ctrl++`, `Ctrl+-`, `Ctrl+0`도 사용할 수 있고, 배율 숫자를 누르면 100%로 돌아갑니다. PDF 배율과는 별도로 적용하며 너비·글자 크기는 다음 실행에도 유지됩니다.

SQLite v13은 번역 effort, 추가 질문 목록과 중단 여부를 추가합니다. 기존 모델 선택·대화·논문·단어 기록은 보존합니다.

## 질문 수정과 대화 버전 (2026-10-08)

각 질문 아래 연필 버튼으로 마지막 질문뿐 아니라 이전 질문도 수정합니다. 답변 도중 보냈던 추가 질문에도 같은 버튼이 있습니다. **수정 후 전송**하면 수정 지점까지의 질문·대화만 참고해 새 답변을 받습니다. 수정 지점 이후의 기존 답변·질문은 새 요청의 문맥에 포함하지 않습니다. 생성 중에는 먼저 답변을 중단하거나 완료한 뒤 과거 질문을 수정할 수 있습니다.

기존 질문·답변·후속 대화는 삭제하지 않습니다. 질문 아래 **이전/다음 버전** 화살표로 수정 전후 대화를 선택하며, 선택한 버전에서 계속 질문할 수 있습니다. 다시 앱을 열어도 마지막으로 선택한 버전을 보여 줍니다. 버전을 바꿀 때는 그 버전 아래에서 가장 최근에 이어진 대화를 엽니다. 수정 취소는 모델을 호출하지 않고, 응답이나 저장이 실패하면 원래 대화와 수정 입력을 유지합니다. 답변을 중단하면 부분 답변을 새 버전으로 저장합니다.

SQLite v14는 `paper_chat.parent_id`에 대화의 연결 관계, `paper_chat_heads`에 논문별 현재 선택을 저장합니다. 기존 선형 기록은 논문별 순서대로 연결합니다. 새 버전과 현재 선택의 저장은 한 트랜잭션으로 처리하며, 요청 도중 다른 대화가 선택되거나 추가되었다면 늦은 답변으로 현재 대화를 덮어쓰지 않습니다.

현재 Linux 설치의 저장 위치는 `~/.local/share/com.papervocabulary.reader/PaperVocabulary/database/vocabulary.db`입니다. 질문·답변·모델·effort·추가 질문·중단 여부와 모든 수정 버전을 이 로컬 데이터베이스에 논문별로 저장합니다. API의 임시 대화와 별도로 앱이 관리하는 기록입니다.

입력창 아래에는 버튼 하나만 표시합니다. 기본은 원형 위쪽 화살표이며, 답변 중 입력이 비어 있으면 같은 위치에서 중단 네모로 바뀝니다. 추가 질문을 입력하면 다시 전송 화살표가 되어 대기열에 질문을 넣을 수 있습니다. 즉시 전달하려면 대기 질문의 **바로 보내기**를 누릅니다. 키보드 안내 문구는 숨기고 Enter 전송·Shift+Enter 줄바꿈 동작은 유지합니다. 구독 잔여 비율 새로고침을 누르면 화살표가 한 바퀴 회전합니다.

검증: 프런트엔드 단위 테스트 75개, Rust 테스트 95개(기존 수동 런타임 테스트 1개 제외), 관련 화면 테스트 12개 통과. 이전 질문·추가 질문 수정, 재실행 후 버전 선택 복원, 실패·취소·중단, 기존 v13 기록 마이그레이션, 다른 논문·오래된 요청 차단, 저장 실패 시 전체 롤백을 포함합니다. 실제 구독 추론 호출은 하지 않았습니다. Tauri release 빌드와 격리된 WebKitGTK 실행에서 SQLite v14 초기화도 확인했습니다.


## 대화 문맥 관리 (2026-10-12)

각 답변은 선택한 대화 버전의 최근 질문·답변 원문과 관련 PDF 발췌를 사용합니다. 요약되지 않은 대화가 12회 또는 48 KB를 넘으면 오래된 부분을 최대 6회씩 묶어 요약하고, 보통 최근 8회는 원문으로 남깁니다. 아주 긴 답변에서는 길이 예산에 맞춰 최근 원문 범위도 줄일 수 있습니다. 입력은 UTF-8 바이트 예산으로 제한하며 모델의 정확한 토큰 잔여량을 뜻하지 않습니다. PDF 발췌는 80 KB, 최근 대화는 48 KB까지 포함하고 현재 질문과 수정된 추가 질문을 별도로 전달합니다. 비정상적으로 긴 개별 대화의 일부를 생략할 때는 입력에 명시합니다.

요약은 주제·정의·근거 페이지·미해결 질문을 보존하고, 중요한 사용자 정정과 조건은 실제 질문에 있는 문구인지 검증한 뒤 인용으로 함께 저장합니다. 오래된 정정도 다음 요약으로 이어지며 인용 길이와 개수에는 제한이 있습니다. 요약을 논문의 사실 근거로 취급하지 않고 제공한 원문을 확인하도록 요청합니다. 요약에는 누락 가능성이 있으므로 원래 질문·답변·수정 버전은 삭제하거나 요약으로 대체하지 않습니다.

요약은 현재 채팅 제공자와 모델로 요청하므로 구독 사용량을 추가로 사용합니다. 변경되지 않은 요약은 재사용합니다. 요약 실패 시 기존 요약과 길이 제한 안의 최근 대화로 답변을 계속하며 채팅창에 문맥 일부 생략 안내를 표시합니다. SQLite v16의 `paper_chat_memory`는 논문과 요약 끝 지점의 대화 ID로 저장하는 파생 캐시입니다. 질문을 과거 시점에서 수정하면 그 시점 이전의 공통 대화에 대한 요약만 사용할 수 있습니다.


## 입력창 아래 모델 선택과 확대 단축키 (2026-10-14)

채팅 연결 제공자·모델·effort 선택을 질문 입력창 바로 아래로 옮겼습니다. Claude 로그인 설정은 입력창 위의 접을 수 있는 영역에 표시합니다. 모델 목록 새로고침이나 설정 변경은 작성 중인 질문을 전송하지 않습니다.

원문·번역·채팅에서 `Ctrl++` 또는 `Ctrl+=`로 확대, `Ctrl+-`로 축소, `Ctrl+0`으로 100%로 돌아갑니다. 숫자 키패드도 지원합니다. 마우스가 있는 영역에 적용하며 채팅 입력창에서 입력 중이면 채팅 글자 크기를 조절합니다. 각 영역의 배율은 독립적이고 Library·Vocabulary에서는 이 단축키가 숨겨진 PDF 배율을 바꾸지 않습니다.
