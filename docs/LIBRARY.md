# 논문 Library

2026-09-22. 폴더와 하위 폴더로 저장된 PDF를 정리하는 Library를 추가했습니다. 추가 요청에 따라 논문과 폴더 삭제도 지원합니다.

## 사용 방법

- 상단 **Library**에서 왼쪽 폴더를 선택합니다. 기존 최상위 PDF는 일반 **기본 폴더**로 이관됩니다. **Library 홈**은 최상위 위치이며, 기본 폴더도 다른 폴더처럼 이름 변경·이동·삭제할 수 있습니다.
- **새 폴더**는 현재 위치 아래에 만듭니다. 폴더를 선택한 뒤 새 폴더를 만들면 하위 폴더가 됩니다.
- **폴더 이름 변경**, **폴더 이동**, **폴더 삭제**로 관리합니다. 자신이나 자신의 하위 폴더로는 이동할 수 없으며 같은 위치에 같은 이름의 폴더를 중복 생성하지 않습니다.
- **PDF 추가**의 파일 선택기 또는 앱 창으로 PDF를 끌어 놓아 현재 폴더에 저장합니다. 여러 PDF를 한 번에 추가하고 파일별 메타데이터를 추출합니다. PDF 이외 파일이나 읽을 수 없는 파일은 실패 내용을 표시하고 나머지는 저장합니다. 자세한 선택·일괄 관리 동작은 [다중 파일 보완](LIBRARY_BATCH.md)을 참고하세요.
- 논문 이름을 누르면 파일 선택기 없이 Reader에서 엽니다. 이름 변경은 표시 제목만 바꾸고 원본 파일명과 PDF 바이트는 유지합니다. Vocabulary의 논문명에도 변경된 제목을 표시합니다.
- 논문별 **폴더로 이동**은 기존 단어/하이라이트와 동일한 논문 ID를 유지하면서 위치만 바꿉니다. 같은 내용의 PDF를 재추가하면 중복 항목 대신 기존 논문을 해당 폴더에 배치합니다.
- Reader에서 여러 파일을 열거나 드롭하면 처음 읽을 수 있는 문서를 열고 나머지도 Library에 보관합니다. 새 문서는 Library 홈에 등록되며, 이미 폴더에 배치한 문서는 Reader로 다시 열어도 폴더를 유지합니다.

## 삭제와 데이터 보존

논문 삭제는 앱에 저장한 PDF 사본과 Library 항목을 제거합니다. 폴더 삭제는 선택한 폴더와 모든 하위 폴더 및 그 안의 논문에 적용합니다. 실행 전에 대상 이름·하위 폴더 수·논문 수를 표시하며 취소할 수 있습니다. Library 홈은 폴더를 담는 최상위 위치입니다.

원본 PDF, Vocabulary 항목·뜻·설명·원문 문맥·조회 횟수, 하이라이트 좌표/색상, API 사용 비용은 유지합니다. Vocabulary에서 과거 논문별 문맥을 계속 확인할 수 있도록 Paper 메타데이터도 유지합니다. 같은 PDF를 나중에 다시 추가하면 기존 하이라이트와 저장 결과를 다시 사용할 수 있습니다. 단어 자체를 지우려면 기존 Vocabulary 선택 삭제를 사용합니다.

삭제된 논문이 Reader에 열려 있으면 해당 문서를 닫습니다. 다른 논문은 그대로 유지합니다. 이미 진행 중인 번역은 기존 동작대로 완료 후 단어 기록에 저장될 수 있으나 Library에 논문을 다시 추가하지는 않습니다.

## 저장 구조

- 기존 SQLite를 버전 8로 이관합니다. 버전 5에 추가한 `library_folders`는 부모 폴더 ID, `library_papers`는 Paper ID와 폴더 배치를 보관합니다. 기존 PDF는 기본 폴더에 등록하며 버전 8은 논문별 메모를 추가합니다.
- 폴더는 앱 내부의 논리적 분류입니다. 실제 PDF는 기존 `papers/<sha256>.pdf` 경로를 사용하므로 폴더 이름/위치 변경 때문에 파일을 재복사하거나 하이라이트 연결을 변경하지 않습니다.
- 폴더 하위 항목 삭제는 하나의 DB 트랜잭션입니다. 실패하면 폴더·논문 배치·삭제 대기 기록을 모두 롤백합니다.
- 파일 시스템과 SQLite 사이의 중단에 대비해 `pending_pdf_deletions`에 삭제할 사본을 기록합니다. 커밋 후 사본을 삭제하고, 파일 삭제에 실패하면 안내 후 다음 앱 실행에서 다시 시도합니다. 완료 전에 같은 PDF를 다시 추가하면 대기 중 삭제를 취소합니다.
- 파일 삭제는 앱의 `papers/` 아래 SHA-256 이름을 가진 사본에만 적용합니다. Paper 메타데이터에 있는 임의 경로를 삭제하지 않습니다.
- DB, 파일 작업과 복원은 로컬에서 수행하며 API 호출이나 비용이 발생하지 않습니다.

## Reader 보존

Library는 별도 화면이며 Reader의 Canvas/Text Layer와 스크롤 위치는 화면 왕복 중 유지합니다. 이미 열린 논문을 Library에서 다시 선택하면 기존 Reader를 재사용합니다. 다른 논문을 열 때만 새 PDF를 로드합니다. 기존 페이지 렌더 큐, 캐시, DPR 제한, Zoom 및 Linux WebKit 스크롤 설정은 변경하지 않았습니다.

## 검증

Library 테스트는 다음 동작을 확인합니다.

- 버전 4 DB에서 기존 데이터 보존과 Library 기본 폴더 등록.
- 폴더 중첩, 한국어/아포스트로피 이름, 동일 위치의 이름 충돌, 이름 변경·이동·재실행 후 복원과 순환 이동 거부.
- PDF 추가/중복 방지/이동/표시 제목 변경, 원본 파일 보존, 일반 Reader의 파일명 표시 회귀.
- 논문·하위 폴더 삭제, 취소, 실패 시 전체 롤백, 다른 폴더 보호.
- Vocabulary/하이라이트/비용 유지, 삭제 후 재추가·기록 복원, 중단된 파일 삭제 재시도와 재추가 시 삭제 취소.
- Library에서 기존 PDF 열기, Reader 캐시 재사용, 누락된 파일·DB 읽기 오류·수정 실패 후 재시도.
- 현재 폴더를 대상으로 하는 Native Drop, 파일 선택 취소, PDF 이외 파일 거부.
- 640px/1200px 화면에서 폴더 계층과 논문 관리 버튼 배치.

실제 유료 API와 사용자 DB를 테스트에 사용하지 않습니다. 데이터 테스트는 임시 SQLite와 PDF 사본, UI 자동 테스트는 기존 Tauri IPC 대역을 사용합니다. 화면과 빌드 로그는 `.tools/library-verification/`에 보관합니다.

- 기존 기능을 포함한 자동 테스트 **107개 통과**: Vitest 19개, Rust 34개, Playwright 54개. 이번 Library 테스트는 Rust 5개와 Playwright 6개입니다.

- 별도 테스트 데이터 폴더를 사용하는 실제 Linux Tauri 앱에서 버전 4 DB 이관, 하위 폴더 생성, 파일 선택기로 PDF 추가, Library에서 다시 열기 및 기존 Highlight 복원을 확인했습니다.
- 실제 UI에서 상위 폴더와 하위 폴더·논문을 삭제한 뒤 앱의 해당 PDF 사본만 제거되고, 원본 파일과 다른 논문이 유지되는 것을 확인했습니다. Vocabulary·문맥·Highlight·API 비용 테이블은 삭제 전후 모든 행이 동일했습니다.

- 기존 Reader 페이지 렌더 큐와 Zoom 구현은 변경하지 않았으며, Reader 화면 왕복 시 Canvas/Text Layer 재사용과 너비 맞춤은 자동 테스트로 확인했습니다.

## Library 사용성 보완 (2026-09-22)

- 상단 화면 순서는 **PDF Reader → Library → Vocabulary**입니다.
- 폴더 또는 논문 제목/행을 누른 채 왼쪽 폴더 위로 드래그하면 폴더를 이동합니다. Library 홈으로 되돌릴 수 있으며 자신·하위 폴더·현재 위치로의 이동은 허용하지 않습니다. 대상 폴더에 테두리를 표시하고, 이동 뒤 의도하지 않은 PDF 열기/폴더 선택을 막습니다. Escape로 드래그를 취소합니다. 기존 이동 버튼도 유지합니다.
- 사이드바의 **＋ 폴더 생성**은 현재 선택한 위치 아래에 만듭니다. 폴더 우클릭의 **새 하위 폴더**는 클릭한 폴더 아래, 논문 우클릭의 **새 폴더**는 해당 논문이 있는 폴더 아래에 만듭니다.
- 우클릭 메뉴는 이름 변경·폴더 이동·삭제 및 논문 정보 수정/열기를 제공합니다. 화면 경계 안에 표시하며 Escape/바깥 클릭/스크롤로 닫습니다. 방향키/Home/End로 메뉴 항목을 선택할 수 있습니다.
- 목록은 **논문 제목 / 중요도 / 메모 / 저자명 / 발행일 / 업로드 날짜** 순서입니다. 중요도는 처음에는 미지정이며 별 1~5개를 선택하면 저장합니다. 현재 선택된 별을 다시 누르면 0개(미지정)로 해제하고, 다른 별을 누르면 해당 개수로 변경합니다. 메모를 포함한 열 제목으로 정렬할 수 있습니다. 정렬 기준과 오름차순/내림차순은 변경 즉시 앱의 로컬 설정 저장소에 보관되어 재실행 후에도 유지됩니다. 설정이 없거나 유효하지 않으면 제목 오름차순으로 시작합니다. 업로드 날짜는 최초 등록 시각의 로컬 날짜로, 재추가·이동·이름 변경 시 바뀌지 않습니다. 좁은 창에서는 목록 안에서 가로 스크롤합니다.
- **논문 정보 수정**에서 제목·저자·발행일을 수정합니다. 발행일은 알려진 정밀도에 따라 연도, 연월 또는 날짜를 입력하며 없는 값을 임의로 채우지 않습니다. 잘못된 날짜는 저장하지 않습니다.

### PDF 제목과 정보 추출

PDF를 추가하거나 Reader에서 파일을 열 때 기존 PDF.js worker로 정보를 읽습니다. XMP/Info의 제목을 우선 사용하고, 누락되거나 기본 문서명/파일명인 경우 첫 페이지의 큰 글씨 제목을 추출합니다. 첫 페이지 텍스트만 추가로 읽으며 Library에서 PDF Canvas를 렌더링하지 않습니다. Reader에서는 이미 로드한 문서를 재사용합니다.

저자는 PDF 메타데이터 또는 제목 아래 저자 줄에서, 발행일은 명시적인 publication/cover date 또는 첫 페이지의 Published/Publication date 표기에서 읽습니다. PDF 생성일·수정일·투고일을 발행일로 사용하지 않습니다. OCR이나 외부 검색/API는 추가하지 않았습니다. 스캔 문서나 제목을 식별할 수 없는 PDF는 파일명을 임시 사용하고 수정 방법을 안내합니다. 기존 원본 파일명/바이트와 콘텐츠 기반 ID는 유지합니다.

SQLite 버전 6은 `papers`에 `authors`, `published_date`, `importance`, `metadata_checked`를 추가합니다. 버전 7에서는 다시 열기/재추가 시 자동 저장 제목과 아직 비어 있는 항목을 재추출하고 직접 수정한 정보(의도적으로 비운 필드 포함)는 보존합니다. 기존 DB의 폴더·Vocabulary·Highlight·API 비용은 유지합니다. 과거에 저장한 PDF는 Library에서 해당 논문을 다시 열면 재추출하며, 전체 Library 파일을 백그라운드에서 일괄 로드하지 않습니다.

- **자동 테스트 118개 통과**: Vitest 23개, Rust 36개, Playwright 59개. 기존 테스트를 유지하고 정보 추출 4개, DB 이관/메타데이터 2개, UI 동작 5개를 추가했습니다.
- 드래그 이동·중첩 폴더 이동·순환 방지·취소·실패 후 재시도, 우클릭 대상의 정확한 폴더 생성/이름 변경, 별점 실패 시 원래 값 유지, 자동 제목 추출·직접 교정·재추가·재실행 복원을 검증했습니다.
- 전체 실행 중 기존 Highlight 클릭 테스트가 페이지 렌더 완료 전에 클릭하는 타이밍 문제가 확인되어, 좌표 테스트 도우미가 `data-rendered-scale`로 렌더 완료를 기다리도록 보완했습니다. Reader의 선택·Highlight·스크롤 구현은 변경하지 않았습니다. 이후 전체 59개 UI 테스트가 통과했습니다.
- TypeScript/Vite, Clippy `--all-targets -- -D warnings`, Tauri 릴리스 및 DEB/RPM/AppImage 빌드를 통과했습니다. 기존 Vite 대형 청크 경고는 유지됩니다.
- 별도 버전 5 테스트 DB를 사용하는 실제 Linux Tauri 앱에서 사이드바/우클릭으로 폴더를 만들고, 파일 선택기로 PDF를 추가하여 실제 제목·저자·발행일 추출과 별 4개 저장을 확인했습니다. 실제 마우스로 논문을 하위 폴더에, 하위 폴더를 기본 폴더에 이동한 뒤 SQLite의 결과와 기존 Vocabulary/Highlight/API 비용 보존을 확인했습니다.
- 최종 AppImage로 재실행한 뒤 이동 결과·논문 정보·중요도를 복원했습니다. 별도 GTK 창에서 실제 OS PDF 드래그를 수행하여 Drop Overlay와 현재 폴더 재추가를 확인했으며, 중복 항목 없이 업로드 날짜와 별점을 유지했습니다.

테스트 데이터와 화면·빌드 로그는 `.tools/library-usability-verification/`에 있습니다. 실제 사용자 DB와 유료 API는 사용하지 않았습니다.

## 기본 폴더·자동 추출·정렬 보완 (2026-09-22)

기존의 가상 기본 폴더를 실제 `library_folders` 행으로 전환했습니다. 이전에 최상위에 있던 논문만 이 폴더에 배치하고, 기존 폴더와 하위 폴더 구조는 유지합니다. 이름이 충돌하면 `기본 폴더 (1)`처럼 구분합니다. 해당 폴더를 이름 변경하거나 드래그하면 포함된 논문과 함께 이동합니다. 재실행 시 이관이 반복되거나 삭제한 기본 폴더가 다시 생성되지 않습니다. 새 논문을 일반 Reader에서 열거나 Library 홈에 추가하면 최상위에 저장되며, 원하는 폴더로 이동할 수 있습니다.

자동 추출은 XMP/Info 메타데이터를 우선 사용하고, 누락된 제목·저자는 첫 페이지의 제목 크기와 저자 줄에서 읽습니다. 분할된 텍스트, 여러 열에 놓인 저자와 숫자 각주를 처리하고 소속·본문을 저자로 넣지 않도록 검사합니다. 발행일은 명시적인 출판/온라인 공개 표기에서 읽으며 약식 영문 월, 숫자 날짜, 한국어 날짜, 학회 논문 발행 연도를 지원합니다. 파일 생성·수정일, 투고·접수일은 발행일로 사용하지 않습니다. PDF에 읽을 수 있는 정보가 없으면 기존의 직접 수정 기능을 사용해야 합니다. 외부 서비스/API/OCR는 추가하지 않았습니다.

이전에는 자동 추출이 빈값으로 끝나도 처리 완료로 잠겨 재추가 시 보완되지 않았습니다. 버전 7에서는 아직 비어 있는 자동 추출 필드를 다시 채웁니다. 기존에 저장된 값과 직접 수정한 제목을 유지하고, 이번 버전에서 직접 비운 필드도 재추출로 덮어쓰지 않습니다. 최초 업로드 날짜·중요도·Vocabulary·Highlight·API 비용은 이 작업으로 바뀌지 않습니다.

정렬은 **제목·저자명·발행일·중요도·업로드 날짜 열 제목**을 눌러 선택합니다. 제목/저자는 기본 오름차순, 날짜/중요도는 기본 내림차순이며 같은 열을 다시 누르면 방향이 바뀝니다. 누락된 값과 미지정 중요도는 양쪽 방향 모두 마지막에 표시합니다. 같은 값은 제목과 논문 ID로 순서를 일정하게 유지합니다. 정렬은 현재 폴더의 표시 순서만 바꾸며 DB를 수정하지 않습니다. 같은 실행 중 폴더/화면을 오가도 기준을 유지하며 앱을 다시 실행하면 제목순으로 시작합니다.

## 앞으로가기·한글 메모 조합 수정 (2026-09-23)

- 상단 **→ 앞으로가기**와 마우스의 앞으로가기 보조 버튼을 추가했습니다. 기존 뒤로가기와 같은 화면·Library 폴더 방문 기록을 사용하며, 한 번 놓을 때 한 단계씩 이동합니다. 뒤로간 뒤 새로운 위치를 선택하면 앞으로 갈 기록을 비우고, 현재 위치 재선택은 기록을 유지합니다. 삭제된 폴더는 양쪽 기록에서 제거하며 이동할 곳이 없거나 파일 열기/Library 저장 중이면 비활성화합니다.
- Pointer/Mouse 이벤트 중복 방지와 WebKit의 Mouse 이벤트만 오는 경우를 두 방향 모두 처리합니다. WebView 자체의 앞/뒤 탐색은 차단하므로 앱 문서가 바뀌지 않습니다. PDF 페이지를 다시 마운트하지 않아 Canvas·Text Layer·배율·스크롤·Highlight를 유지합니다.
- 한글 문제는 React 저장 지연이 아니라 Linux 네이티브 입력기의 설정이 원인이었습니다. 설치된 [Wry 0.55.1의 WebKitGTK 초기화](https://docs.rs/wry/0.55.1/src/wry/webkitgtk/mod.rs.html)는 `set_enable_preedit(false)`로 입력 칸 내 조합을 끕니다. 기존 실행 파일과 IBus Hangul에서 별도 작은 조합 창을 재현했습니다. 앱 초기화에서 `set_enable_preedit(true)`로 복원해 입력 위치에서 바로 조합·삭제하도록 했습니다. 기존 부드러운 스크롤 비활성 설정은 유지하며 시스템 입력기 설정과 의존성 코드는 변경하지 않았습니다.
- 메모는 IME 조합 상태를 추적하고 조합 중 Escape가 편집 전체를 취소하지 않도록 합니다. 일반 Escape 취소·영문 입력·기존 저장 방식은 유지합니다. DB 스키마 변경은 없습니다. 네이티브 입력 설정 변경은 새 실행 파일을 시작할 때 적용됩니다.

### 검증 결과

- **153개 자동 테스트 통과**: Vitest 39개, Rust 41개, Playwright 73개. 이동 기록 왕복·새 분기·삭제 폴더 정리 3개와 화면 통합 검사 5개를 추가했습니다.
- 앞으로가기 버튼, 실제 Chromium 마우스 Forward 입력, WebKit의 Mouse 전용 이벤트, 작업 중 비활성 입력 위에서 탐색 차단, 브라우저 기본 탐색 방지, Reader 노드 동일성·배율·스크롤·Highlight 캐시 재사용을 검사했습니다.
- 브라우저 IME 조합 이벤트로 중간 글자 수정·삭제, 연속 조합, 조합 중 저장, 재실행, 조합 중 Escape 보호와 일반 Escape 취소를 검사했습니다. 기존 PDF 선택·번역·Highlight·Zoom·스크롤·드롭, Vocabulary/내보내기, Library 정렬·메모·뒤로가기 테스트도 모두 통과했습니다.
- 별도 Xvfb 화면·DBus/IBus·SQLite를 사용하는 실제 Linux 앱과 최종 AppImage에서 한글을 입력했습니다. 최종 AppImage의 실제 입력 칸 값을 접근성 API로 읽어 `한 → Backspace → 하 → Backspace → ㅎ`를 확인했고, 계속 입력한 `한글\n연속 입력`이 마지막 글자 조합 중 저장해도 SQLite에 정확히 보관됨을 확인했습니다. 재실행 후 메모 복원도 확인했습니다.
- 최종 AppImage에서 실제 OS 마우스 Button 8/9와 상단 두 버튼으로 기본 폴더·하위 Research 폴더·Vocabulary를 한 단계씩 왕복했습니다. 테스트 메모와 격리 PDF 경로 외 모든 DB 데이터가 기존 사본과 같고 SQLite 무결성 검사가 통과했습니다.

재현 화면·테스트 로그·격리 데이터는 `.tools/forward-ime-verification/`에 보관합니다. 테스트는 사용자 DB와 유료 API를 사용하지 않았습니다.
