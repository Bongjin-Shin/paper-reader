# Ctrl+Z / Ctrl+Shift+Z

2026-09-23. 사용자 지정 범위: Vocabulary·Highlight 삭제와 Library 이동·삭제·정보 수정 전체.

## 동작

- Ctrl/Command+Z: 직전 작업 실행 취소. Ctrl/Command+Shift+Z: 다시 실행.
- Vocabulary 삭제는 모든 논문의 문맥·하이라이트·캐시와 조회 횟수까지 복원합니다. 하이라이트만 삭제한 작업은 위치·색상·연결을 복원하고 단어장을 변경하지 않습니다.
- Library 폴더 생성·이름 변경·이동·하위 폴더 포함 삭제, 논문 개별/일괄 이동·삭제, 제목·저자·발행일·메모·중요도 수정을 지원합니다. 일괄 작업은 한 단계입니다.
- 현재 실행 중 최근 50개 데이터 작업을 기억합니다. 새 성공 작업은 redo를 비우고 실패나 실제 변경 없는 저장은 기록하지 않습니다. 재시작하면 기록은 초기화됩니다.
- 새로운 PDF 추가 및 새 조회는 redo를 비우지만 undo에 추가하지 않습니다. 화면 탐색·선택·정렬·확대·인쇄·내보내기·API 비용은 대상이 아닙니다.
- 논문 채팅의 새 질문·질문 수정 입력란은 별도의 글 편집 기록으로 Ctrl+Z / Ctrl+Shift+Z를 지원합니다. 연속 타이핑, 한글 조합, 붙여넣기와 삭제를 되돌리고 커서·선택 영역도 복원합니다. 새 질문의 편집 기록은 같은 논문의 채팅창을 닫았다 열어도 유지되며, 전송하면 초기화됩니다. 전송된 대화나 Library 작업에는 영향을 주지 않습니다. 새 입력 후에는 다시 실행 기록을 비웁니다.
- 나머지 글 입력란은 WebView의 글 편집 실행 취소를 사용합니다. 한글 조합, Alt 조합, 키 자동 반복은 앱 실행 취소를 요청하지 않습니다. 작업 진행 중 중복 요청, 파일 추가·삭제·조회 중 실행 취소도 차단합니다.

## 데이터 보호

DB 잠금 안에서 SAVEPOINT로 작업 전후를 비교하고 바뀐 행만 메모리에 보관합니다. 실행 취소/다시 실행도 전체를 하나의 트랜잭션으로 적용하고 외래 키를 확인합니다. 오류·제약 조건 실패·이후 변경과의 충돌이 발생하면 부분 복원 없이 롤백하며 취소 기록을 유지합니다. 필드 수정은 실제 바뀐 필드만 복원하므로 별도로 추가된 뜻·API 비용·다른 정보는 보존합니다.

삭제된 Vocabulary·문맥·Highlight ID는 기록에 남아 있는 동안 새 조회에서 재사용하지 않습니다. 삭제 뒤 새로운 단어를 저장해도 기존 항목을 복원할 수 있습니다. 같은 단어를 새로 조회하는 등 충돌하는 변경이 있으면 데이터를 덮어쓰지 않고 오류를 안내합니다.

Library의 삭제 대기 큐는 복원 가능한 PDF 사본을 잠시 보존합니다. undo로 Library에 복구하면 삭제 대기 항목도 취소되고 redo로 다시 삭제할 수 있습니다. 원본 파일에는 쓰지 않습니다. 누락된 사본은 복원 성공으로 표시하지 않습니다. 앱 시작 시 이전 실행의 삭제 대기 사본을 기존 정리 절차로 처리합니다. DB 스키마 버전 8과 기존 데이터 위치는 그대로입니다.

프런트엔드는 복원 후 Library·Vocabulary·현재 문서 제목과 Highlight를 갱신합니다. 현재 Reader 문서의 Canvas/Text Layer를 다시 만들지 않습니다. 삭제된 문서를 복구하면 Library에서 다시 열 수 있고, 열려 있는 논문의 삭제를 redo하면 Reader를 닫습니다.

## 검증

Rust 9개 테스트: 문맥·캐시·Highlight·조회 횟수와 실제 비용 보존, Highlight 색상·좌표, 연속 이동·정보·메모·중요도·폴더 복원, PDF 사본 임시 보관·재시작 정리, 일부 복원 실패의 원자성·재시도, 누락 사본·충돌 보호, 50개 한도·redo 초기화·무변경 저장, 변경 필드만 복원, 새 조회와 삭제 ID 충돌 방지.

Playwright 7개 테스트: Vocabulary 삭제 undo/redo와 비용·캐시·Canvas 보존, Highlight 삭제, 폴더 트리·논문 이동·삭제 복원과 다시 열기, 메모·중요도·제목 복원, 실제 글 입력 undo와 IME 보호, 실패·중복 입력·새 작업·재시작, 진행 중 삭제 차단.

로그와 별도 데이터로 실행한 네이티브 검증 자료는 `.tools/undo-verification/`에 보관합니다.

전체 회귀 테스트 **198개 통과**: Vitest 46, Rust 53, Playwright 99. TypeScript/Vite, Rust fmt/Clippy, Tauri release 빌드도 통과했습니다. 기존 Reader 스크롤·선택·Zoom·Cache, Vocabulary 인쇄·내보내기·다중 선택, Library 업로드·폴더·메모·탐색 회귀를 포함합니다.

바탕화면 `.desktop`을 통해 설치한 AppImage를 별도 Xvfb 화면·테스트 DB에서 실행했습니다. 실제 Ctrl+Z/ Ctrl+Shift+Z로 두 단어 삭제를 반복 취소·재실행하고 단어·문맥·하이라이트 수가 모두 4→2→4→2→4로 일치하는지 SQLite에서 확인했습니다. 논문이 포함된 폴더 삭제 역시 Library 배치 3→2→3, 삭제 대기 0→1→0, PDF 사본 3개 유지로 검증했습니다. 복원 PDF를 실제 Reader에서 열었고 그 삭제를 redo하면 문서가 닫히는 동작도 확인했습니다. 모든 단계에서 무결성·외래 키 검사가 통과했습니다.

화면 갱신 시 이전 삭제 성공/오류 메시지가 남지 않도록 정리했으며 이 확인을 포함한 전체 Playwright 99개와 Tauri 빌드·패키징을 다시 수행했습니다. 사용자 DB와 유료 API는 테스트에 사용하지 않았습니다.
