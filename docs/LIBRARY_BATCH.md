# Library 다중 파일 업로드·선택·일괄 관리

2026-09-23. 여러 PDF 추가, PDF 다중 선택과 일괄 폴더 이동·삭제 요청을 구현했습니다.

## 업로드

- Library의 `PDF 추가`와 Reader의 `PDF 열기` 파일 선택기에서 여러 파일을 선택할 수 있습니다. 앱 창으로 여러 파일을 함께 끌어 놓아도 처리합니다.
- Library에서는 업로드를 시작한 폴더에 저장합니다. Reader에서는 처음 읽을 수 있는 PDF를 열고 나머지도 Library에 보관합니다. Reader에서 기존 논문을 다시 열 때는 기존 폴더 배치를 유지합니다.
- 복사와 제목·저자·발행일 추출은 파일별로 순서대로 실행합니다. PDF를 한꺼번에 메모리에 읽거나 모든 페이지 Canvas를 렌더링하지 않습니다. 메타데이터 추출용 임시 PDF.js 문서는 다음 파일로 넘어가기 전에 정리합니다.
- PDF 확장자·내용 헤더·기존 256MB 제한을 파일별로 검사합니다. 잘못된 파일이나 PDF 이외 파일이 섞여 있어도 나머지 PDF는 저장하고 실패한 파일명을 표시합니다. 암호·내용 손상으로 메타데이터를 읽지 못한 경우에는 정보 수정 안내를 표시합니다.
- 동일 경로와 동일 PDF 내용은 중복 항목으로 추가하지 않습니다. 기존 수동 제목·정보·메모·중요도와 최초 업로드 날짜를 보존합니다.
- OS에서 실제 드롭한 경로 목록과 IPC 경로 목록을 비교하고 한 번 사용한 드롭 권한은 소비합니다. 별도의 임의 경로 업로드 권한은 추가하지 않았습니다.

## 선택과 일괄 작업

- 체크박스 또는 Ctrl 클릭으로 해당 PDF만 선택·해제합니다. macOS의 Command 키도 같은 동작입니다. Shift 클릭은 마지막 기준 항목부터 현재 항목까지 현재 화면의 정렬 순서로 선택합니다. Ctrl+Shift는 기존 선택에 구간을 추가합니다.
- PDF 제목을 일반 클릭하면 기존처럼 Reader에서 엽니다. Ctrl/Shift 클릭은 파일을 열지 않습니다. 메모·중요도·개별 액션 버튼은 기존 편집 동작을 유지합니다.
- 목록의 빈 영역에서 드래그하면 사각형에 닿은 행을 선택합니다. Ctrl을 누른 채 드래그하면 기존 선택에 추가합니다. 위·아래 가장자리에서는 자동 스크롤하고, Escape로 진행 중인 드래그 선택을 취소하면 이전 선택으로 돌아갑니다.
- `전체 선택`은 현재 폴더의 모든 PDF를 대상으로 합니다. 정렬 변경은 선택한 ID를 유지하고, 폴더나 화면 이동은 선택을 해제합니다. 부분 선택 표시도 제공합니다.
- `선택 이동`에서 대상 폴더를 고르거나, 선택한 PDF 중 하나를 왼쪽 폴더에 드래그해 함께 옮깁니다. 기존 폴더 드래그 이동·순환 이동 금지·단일 PDF 드래그 동작을 유지합니다.
- `선택 삭제`는 정확한 대상 이름과 개수를 보여주고 확인 후 실행합니다. 선택한 여러 PDF의 우클릭 메뉴에서도 일괄 이동·삭제를 실행할 수 있습니다.

## 데이터와 성능

일괄 이동·삭제는 각각 하나의 SQLite 트랜잭션입니다. 대상 중 하나가 사라졌거나 DB 쓰기가 실패하면 모든 변경을 롤백합니다. UI도 선택과 입력한 목적지를 유지해 다시 시도할 수 있습니다. 파일 사본 삭제는 커밋 후 기존 삭제 대기 큐로 처리하며, 실패한 사본 정리는 다음 실행에서 재시도합니다.

Library에서 삭제해도 원본 파일·Paper 메타데이터·Vocabulary·Context·Highlight·API Cache·비용은 보존합니다. 삭제한 PDF가 Reader에 열려 있으면 해당 문서를 닫고, 다른 문서는 유지합니다. 같은 PDF를 다시 추가하면 기존 기록을 사용할 수 있습니다. DB 스키마는 버전 8 그대로입니다.

사각형 선택의 행 좌표는 시작 시 한 번 측정하고 포인터·자동 스크롤 처리는 requestAnimationFrame으로 묶습니다. 선택 ID가 달라질 때만 React 선택 상태를 갱신합니다. Reader의 페이지 캐시·Canvas/Text Layer·Zoom·스크롤 보간 설정은 변경하지 않았습니다.

## 검증

전체 **172개 자동 테스트 통과**: Vitest 44개, Rust 44개, Playwright 84개. 기존 159개에 선택 규칙 3개, DB/파일 배치 처리 3개, 화면 통합 7개를 추가했습니다.

- 여러 파일 선택/드롭, 파일별 메타데이터 추출, 일부 실패·중복·다시 열기·잘못된 목적지, 기존 Reader 유지와 로컬 보관.
- Ctrl 선택·해제, 양방향 Shift 범위와 현재 정렬 순서, Ctrl+Shift, 전체·부분 선택과 폴더 이동 시 해제.
- 양방향 사각형 선택·Ctrl 추가·Escape 복원·가장자리 자동 스크롤·포인터 종료 후 중지·메모 편집 보호.
- 여러 PDF 드래그 이동과 우클릭 메뉴, 일괄 폴더 이동·삭제의 취소·실패·재시도·재실행.
- DB 트리거로 두 번째 변경을 실패시켜 첫 번째 변경까지 롤백되는지 확인. 파일 사본·원본·선택하지 않은 논문·Vocabulary·Highlight·비용 및 재추가 후 복원 보존.
- 기존 Reader 선택·Highlight·버블·Zoom·스크롤·PDF 드롭, Vocabulary·인쇄/PDF·Cache, Library 폴더·정렬·메모·탐색 회귀.

TypeScript/Vite, Rust fmt/Clippy, Tauri 릴리스 빌드와 DEB/RPM/AppImage 패키징을 완료했습니다. 기존 Vite의 큰 번들 경고는 빌드를 막지 않습니다. 로그와 검증 자료는 `.tools/library-batch-verification/`에 보관합니다. 사용자 DB와 실제 유료 API는 검증에 사용하지 않았습니다.

최종 AppImage를 별도 Xvfb 화면과 격리한 SQLite DB에서 실행해 Linux WebKitGTK 동작도 확인했습니다. 실제 파일 선택창으로 정상 PDF 3개와 손상 파일 1개를 함께 선택해 정상 파일만 저장했습니다. 별도 GTK 창에서 PDF 2개와 텍스트 파일 1개를 OS 드래그 앤 드롭해 PDF만 추가했습니다. 5개 PDF 모두 제목·저자·발행일 추출을 확인했습니다.

Ctrl 클릭으로 떨어진 두 행을 선택하고 Shift 클릭으로 세 행을 선택한 뒤, 선택한 파일들을 사이드바 폴더로 함께 드래그해 이동했습니다. 빈 영역의 사각형 드래그로 두 행을 선택해 실제 삭제 확인창의 대상과 일치하는 파일만 삭제했습니다. SQLite를 별도 연결로 확인해 폴더 배치·남은 사본 3개·원본 5개 보존, 무결성 검사 통과와 외래 키 위반 없음까지 검증했습니다. 상세 결과는 `native-checks.json`, 화면은 같은 검증 폴더의 `native-*.png`에 보관합니다.
